# IMPLEMENTATION-PLAN.md — План реализации PWA онлайн-записи для nail-студий

## Цель проекта
Создание масштабируемой, отказоустойчивой, брендируемой PWA-системы онлайн-записи клиентов в студии маникюра и nail-бары.
Система обеспечивает мгновенный ребрендинг под новую студию через один конфигурационный файл `business.json` и набор медиа-ассетов, при сохранении полной изоляции и независимой работы всех ранее созданных студий.

---

## Архитектурные инварианты
1. **Multi-tenant архитектура:**
   - Единый JS/CSS-бандл (Cloudflare Pages), единый инстанс Supabase.
   - Все зависимые таблицы содержат `tenant_id` и используют составные составные внешние ключи `FOREIGN KEY (tenant_id, ...)` для предотвращения утечек.
   - Маршрутизация: `/s/{slug}/` (клиентская часть), `/s/{slug}/b/{token}` (просмотр и перенос своей записи без пароля), `/s/{slug}/owner/` (кабинет владельца).
2. **Конвейер конфигурации (Tenant Pipeline):**
   - Входной формат: `tenants/{slug}/business.json` + `tenants/{slug}/assets/`.
   - Конвейер включает скрипты: `tenant:new`, `tenant:validate`, `tenant:publish`, `tenant:verify`.
   - Переиздание конфигурации идемпотентно и не затрагивает существующие записи, клиентов и загруженные фотографии.
3. **Исключение перекрытий (No Overbooking) через PostgreSQL `EXCLUDE`:**
   - Таблица `resource_occupancies` с ограничением `EXCLUDE USING gist (tenant_id WITH =, resource_id WITH =, time_range WITH &&)`.
   - Ресурсы: мастера (`STAFF`) и рабочие места/столы/педикюрные кресла (`WORKPLACE`).
   - Расчет слотов учитывает длительность услуги, буферное время между клиентами, рабочие часы студии, график мастера, перерывы и исключения расписания.
4. **Атомарные транзакции бронирования:**
   - Создание, перенос (`reschedule`) и отмена (`cancel`) выполняются на стороне PostgreSQL через хранимые функции `SECURITY DEFINER`.
   - Клиент никогда не передает цену, длительность или внутренние ID ресурсов.
   - Неудачный перенос сохраняет исходную запись без потерь.
5. **Беспарольный доступ для клиентов, Supabase Auth для владельцев:**
   - Клиент получает защищенный токен в URL при подтверждении записи. В БД хранится только `SHA-256` хэш токена.
   - Владелец входит по email/паролю через Supabase Auth с обязательной проверкой роли в таблице `tenant_memberships`.
6. **Строгие RLS и изоляция данных:**
   - Роль `anon` имеет доступ только к публичным данным тенанта (активные услуги, активные мастера, доступные слоты через RPC).
   - Личные данные других клиентов, финансовая отчетность и системные токены недоступны для `anon`.
7. **AI-ассистент с безопасным Tool Loop:**
   - Вызовы модели через Edge Function `ai-chat` с конфигурируемыми `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.
   - Tool Loop с жестким whitelist инструментов: публичные (поиск услуг, свободных окон, правила подготовки) и защищенные для владельца (статистика, обзор дня).
   - Атомарные счетчики лимита запросов и бюджета в БД. Fallback при недоступности AI: обычная запись работает автономно.
8. **SQL-статистика студии:**
   - Разделение статусов: создана, подтверждена, завершена, отменена, неявка.
   - Точный учет фактической выручки (только завершенные/оплаченные) vs прогнозируемой стоимости.
9. **Динамический PWA Shell:**
   - Индивидуальные метаданные (title, theme-color, apple-touch-icon, manifest.webmanifest) под каждого тенанта по его slug.
   - Service worker с кэшированием статики и изоляцией приватных данных.
10. **Очередь уведомлений (Outbox Queue):**
    - Таблица `notification_jobs` с поддержкой дедупликации, блокировок (`leased_until`) и повторных попыток (`retry_count`).
    - Web Push по стандарту VAPID + скачивание календаря `.ics`.

## Этапы реализации

### Этап 1: Архитектура БД, PostgreSQL/Supabase схема, миграции и функции бронирования
- [x] Определение структуры миграций в `supabase/migrations/`.
- [x] Таблицы: `tenants`, `service_categories`, `services`, `service_options`, `masters`, `master_services`, `workplaces`, `master_schedules`, `studio_business_hours`, `schedule_exceptions`, `bookings`, `booking_services`, `booking_options`, `resource_occupancies`, `clients`, `payments`, `notification_jobs`, `booking_audit_logs`, `rate_limit_usage`, `tenant_memberships`.
- [x] Составные внешние ключи `(tenant_id, id)` и расширение `btree_gist`.
- [x] Ограничение `EXCLUDE USING gist (tenant_id WITH =, resource_id WITH =, time_range WITH &&)` в `resource_occupancies`.
- [x] SQL RPC-функции:
  - `create_booking_atomic(...)` — атомарная бронь мастера, рабочего места, создание записи, генерация хэша токена и задачи в outbox.
  - `reschedule_booking_atomic(...)` — безопасный перенос с освобождением старых слотов и блокировкой новых.
  - `cancel_booking_atomic(...)` — отмена записи и освобождение ресурсов.
  - `block_master_time_atomic(...)` — блокировка времени мастера владельцем (перерыв/отпуск).
  - `get_available_slots(...)` — расчет свободных слотов с учетом графика мастера, часов студии, буферов и занятостей.
  - `lookup_booking_by_token(...)` — публичный доступ клиента к своей записи по токену.
  - `get_studio_stats(...)` — аналитические показатели студии за период.
- [x] RLS политики и права `GRANT` для ролей `anon`, `authenticated`, `service_role`.
- **Верификация Этапа 1:** Запуск SQL-тестов схемы и RPC-процедур.

### Этап 4: Премиальный мобильный клиентский UX студии маникюра
- [x] Главный экран студии (`ClientBookingPage`):
  - Эстетичный Hero с логотипом, фотографией студии, адресом и часами работы.
  - Категории услуг: Маникюр, Покрытие гель-лаком, Снятие, Укрепление, Наращивание, Педикюр, Дизайн ногтей, Комплексы.
  - Карточки услуг с фото, описанием, фиксированной ценой и длительностью.
  - Модальное окно/BottomSheet выбора дополнительных опций к услуге (снятие, укрепление, сложность дизайна 1-10 ногтей, ремонт).

  - Выбор даты и времени: календарь + интерактивная сетка реально свободных окон, полученных от сервера.

  - Итоговая сводка перед подтверждением.
  - Отправка запроса в `create_booking_atomic` и получение крипто-токена.

  - Скачивание события в календарь (.ics).

### Этап 5: Мобильный кабинет владельца студии (Owner Portal)
- [x] Авторизация владельца (`/s/:slug/owner/login`) через Supabase Auth с проверкой прав `tenant_memberships`.
- [x] Рабочий дашборд владельца (`/s/:slug/owner`):
  - **Сегодня:** сводка дня, ближайшая запись, количество свободных окон, быстрый статус.
  - **Записи:** фильтры по статусам (Создана, Подтверждена, В процессе, Завершена, Отменена, Неявка), поиск по клиенту/телефону.
  - **Календарь:** просмотр расписания по мастерам и рабочим местам на день/неделю.
  - **Ручное создание записи:** возможность владельцу записать клиента напрямую.
  - **Блокировка времени:** создание блокировок перерывов/отпусков мастера с немедленным исключением слотов из публичной записи.
  - **Клиенты:** база постоянных клиентов с историей визитов и суммой покупок.
  - **Мастера и услуги:** просмотр списка мастеров и каталога услуг.
  - **Статистика:** аналитика на основе SQL `get_studio_stats` (создано, завершено, отменено, выручка).
- **Верификация Этапа 5:** Корректное отображение дашборда и переход статусов записей.
