# AGENTS.md — Правила и Инструкции для Агентов разработки (v2)

## Роль и контекст
Вы разрабатываете законченное, высоконагруженное, масштабируемое multi-tenant PWA-приложение для онлайн-записи клиентов в nail-студии и beauty-салоны.
Цель: готовый к коммерческой демонстрации и эксплуатации продукт, развёртываемый на Vercel + Supabase, поддерживающий моментальное переодевание под любого клиента через один файл `business.json` и набор фотографий.

## Архитектурные правила
1. **Мультитенантность и изоляция студий:**
   - Каждый запрос обязан изолировать данные по `tenant_id`. Внешние ключи между сущностями одного тенанта должны быть составными `(tenant_id, id)` с `FOREIGN KEY (tenant_id, fk_id) REFERENCES target_table(tenant_id, id)`.
   - Публичные маршруты: `/s/{slug}/` и `/s/{slug}/b/{token}`.
   - Кабинет владельца: `/s/{slug}/owner/` с защищённым входом `/s/{slug}/owner/login`.
   - Владелец одной студии ни при каких условиях не должен видеть данные другой студии. Защита обеспечивается на сервере через Supabase RLS и `tenant_memberships`.

2. **Атомарность слотов и блокировок (No Overbooking & Idempotency):**
   - Бронирование мастера и отдельного ресурса (например, педикюрного кресла) фиксируется в таблице `resource_occupancies` с ограничением PostgreSQL `EXCLUDE USING gist (tenant_id WITH =, resource_id WITH =, time_range WITH &&)`.
   - Если процедура требует одновременно мастера и рабочего места, они занимаются в одной неделимой транзакции (оба или ни одного).
   - Повторное нажатие кнопки подтверждения защищено через `idempotency_key` (не создаёт дубликат).
   - Перенос записи выполняется атомарно: при невозможности занятия нового слота старая запись остаётся действительной.

3. **Фронтенд и стек технологий:**
   - Стек: React 19, TypeScript strict, Vite, pnpm, React Router, TanStack Query, Zod, date-fns / date-fns-tz.
   - Интерфейс: Astryx Design System (`@astryxdesign/core`, `@astryxdesign/theme-neutral`, `@stylexjs/stylex`) и Phosphor Icons (`@phosphor-icons/react`).
   - Настоящий стеклянный эффект: `liquid-gl` с плавным fallback на CSS `backdrop-filter` при отключенных эффектах или неподдерживаемых устройствах.
   - PWA: `vite-plugin-pwa` и Workbox для офлайн-кэширования и установки на домашний экран со своей иконкой и без адресной строки.
   - Стилизация: тёмный, аккуратный интерфейс: глубокий чёрный фон `#000000`/`#0A0A0C`, контрастный белый текст `#FFFFFF`, акцентный цвет по умолчанию `#4690FF` (динамически переопределяется из конфига студии).

4. **AI-Помощники (Клиент и Владелец):**
   - Работают через серверные функции Vercel с ключом OpenAI SDK на сервере (модель конфигурируется через `OPENAI_MODEL`).
   - Помощники получают факты исключительно через вызовы инструментов (услуги, мастера, реальные слоты, контакты) и не придумывают данные.
   - Помощник клиента не имеет доступа к базе клиентов и чужим записям.
   - Помощник владельца только читает данные и не изменяет записи по собственной инициативе.
   - Действует лимит запросов в минуту и дневной бюджет.

5. **Управление студией и конвейер:**
   - Настройки каждой студии хранятся в `tenants/<slug>/business.json`.
   - Новая студия создаётся за минуты скриптами: `pnpm tenant:new <slug>`, `pnpm tenant:validate <slug>`, `pnpm tenant:publish <slug>`, `pnpm tenant:verify <slug>`.
   - До полной проверки студия открывается как образец (`sample`).

6. **Тестирование:**
   - Vitest для расчёта слотов, проверки Zod-схем, идемпотентности и бизнес-логики.
   - Playwright для сквозных проверок на мобильных и десктопных устройствах.
