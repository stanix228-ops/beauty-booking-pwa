# AGENTS.md — Правила и Инструкции для Агентов разработки

## Роль и контекст
Вы разрабатываете высоконагруженное, масштабируемое multi-tenant PWA-приложение для онлайн-записи клиентов в nail-студии и салоны маникюра.
Цель: законченный работающий продукт, готовый к деплою на Cloudflare Pages + Supabase, поддерживающий переодевание под любого клиента через один файл `business.json` и набор ассетов.

## Архитектурные правила
1. **Мультитенантность в каждом запросе и таблице:**
   - Каждый запрос обязан проверять и изолировать данные по `tenant_id`.
   - Внешние ключи между сущностями одного тенанта должны быть составными `(tenant_id, id)` с `FOREIGN KEY (tenant_id, fk_id) REFERENCES target_table(tenant_id, id)`.
   - Публичные маршруты: `/s/{slug}/` и `/s/{slug}/b/{token}`.
   - Кабинет владельца: `/s/{slug}/owner/`.

2. **Атомарность слотов и блокировок (No Overbooking):**
   - Бронирование мастера и рабочего места фиксируется в таблице `resource_occupancies`.
   - Используется ограничение PostgreSQL `EXCLUDE USING gist (tenant_id WITH =, resource_id WITH =, time_range WITH &&)`.
   - Создание, перенос и отмена записи выполняются исключительно через хранимые процедуры (RPC) в транзакциях.

3. **Безопасность клиентов и владельца:**
   - Клиент записывается без пароля и регистрации. Доступ к записи осуществляется по криптографическому токену (URL токен + SHA-256 хэш в БД).
   - Владелец студии авторизуется через Supabase Auth с обязательной проверкой `tenant_memberships` на сервере. Публичная регистрация владельцев закрыта.
   - Строгие политики RLS для всех таблиц: `anon` не имеет прямого доступа к чужим записям, номерам телефонов клиентов и внутренним токенам.

4. **Целостность цен и параметров:**
   - Клиентский интерфейс никогда не передает цену, длительность или tenant_id как определяющие значения.
   - Сервер рассчитывает и фиксирует историческую цену (`price_at_booking`) и продолжительность на момент создания записи.

5. **Фронтенд и Дизайн:**
   - Стек: React 19, TypeScript strict, Vite, Tailwind CSS v4, Astryx (`@astryxdesign/core`, `@astryxdesign/theme-neutral`, `@stylexjs/stylex`), shadcn/ui.
   - Никаких захардкоженных названий студий, услуг, мастеров или цен в коде компонентов (`src/`). Все данные поступают из `TenantContext` и Supabase.
   - Дизайн премиального мобильного бьюти-приложения: темная эстетика (obsidian/deep warm graphite), акцентные цвета из конфига тенанта, крупные превью работ, плавные шторки (bottom sheets), безопасные отступы (safe area).

6. **Тестирование и Конвейер:**
   - Скрипты конвейера: `tenant:validate`, `tenant:new`, `tenant:publish`, `tenant:verify`.
   - Каждый этап завершается верификацией: typecheck, build, unit/integration-тесты, playwright E2E.
